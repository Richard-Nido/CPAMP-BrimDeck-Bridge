# CPAMP–BrimDeck Bridge v1.2.0

- 额度来源可选“CPAMP 已有额度快照”或“CPA 代理查询官方额度”，旧配置默认保留 CPAMP。
- CPAMP 模式合并持久化快照与 auth-files 运行时额度，按同账号、同窗口的额度观测时间取最新有效值，避免较新的运行时额度被旧快照遮住。
- 修正 field_sources.quota 时间与 current_cycle 窗口结束时间读取；兼容旧 all / 新 codex_main 窗口选择，保留已停用生命周期。
- 官方模式只自动查询已勾选的 Codex 账号，失败保留上次官方值、标过期并报告错误，不静默切换来源。
- 新增独立 Custom 额度脚本，可选官方或 CPAMP 模式。每次动态获取 auth_index，由 CPA 服务端使用对应凭证请求官方额度；配置完成后可退出 Bridge。
- 新增 CPAMP 完整统计与 CPA 原生统计独立脚本。按用户选择，CPA 缺少完整统计接口时直接报告不支持，不降级为局部请求计数。本机 CPA 8.0.47 属于此情况；完整统计请使用 CPAMP 直连脚本。
- 接入页可复制带精确账号选择器的直连脚本，管理密钥仍在 BrimDeck 单独填写，不嵌入脚本。
- 保存账号选择后立即刷新，后台继续按配置周期读取；health 报告单账号官方查询失败。

升级：退出旧程序，保留 state，覆盖新版发行文件。原桥接脚本仍可使用；直连模式需填写 CPA / CPAMP 对应地址与管理密钥。使用 Custom 时数据仍展示为配额行，不写入 BrimDeck 底部内置统计区。

实测环境：Windows 11 x64，CPAMP v1.14.10、CPA v8.0.47、BrimDeck 1.2.1。详细测试与边界见 TEST_REPORT.md。发行包不包含个人配置、密钥、数据库或私人截图。
